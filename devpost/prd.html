VibeGuide PRD Approved

Product Requirements Document (PRD) — UX architecture, interaction flows, visual styling, and behavioral acceptance criteria.

User Journey & Interaction Flow

1
The Arrival

User sees clean, dark-mode single-page layout with headline "VibeGuide." and subtle aesthetic input lines.

2
Anchor Input & Validation

User chooses Tokyo or NYC, fills 1 to 3 anchors (Music, Film, Vibe). Inline shake/highlight if empty.

3
Dynamic Generation Feedback

Button transitions to spinner with cycling copy: "Analyzing your taste..." → "Mapping the city..." → "Writing your itinerary...".

4
Timeline & Vibe Storytelling

Input fades; vertical 4-stop itinerary appears with prominent "Why It Fits Your Vibe" narrative callouts visible directly on screen.

5
Loop Back

"Plan Another Day" ghost CTA smoothly returns the user back to the input state to explore another vibe.

Core Functional Specifications

Input & Validation

  • • City dropdown (Tokyo, New York).
  • • 3 minimalist underlined inputs.
  • • Requires at least 1 anchor to submit.
  • • Non-blocking inline validation.

Loading Experience

  • • High-contrast CTA morphs to spinner.
  • • 3-stage status text rotation.
  • • Graceful fallback handling on timeout.

Timeline & Explanations

  • • 4 distinct stops (Morning to Night).
  • • Non-collapsed vibe explanation blocks.
  • • Thin connecting line for journey feel.

Error Resilience

  • • Friendly editorial error card on failure.
  • • "Try Different Anchors" reset button.
  • • Zero technical stack traces shown to users.
